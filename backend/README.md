# CrewSignal ground server

A small Node + TypeScript service that stores, routes, delays and audits
packets. It assigns no clinical meaning: there is no diagnosis, no health score
and no model in the decision path. Quality flags come from the same demo rules
the frontend uses.

The server never fakes a receipt. `sent`, `delivered` and `acknowledged` exist
only because the server stored the timestamp that produced them.

## Requirements

- Node 24 (tested with 24.19.0)
- npm 11

`better-sqlite3` installs from a prebuilt binary on Windows and Node 24. If a
future Node version has no prebuild, install may need build tools; the code is
written against `better-sqlite3` and will not silently fall back to
`node:sqlite`.

## Environment

| Variable | Default | Meaning |
| --- | --- | --- |
| `PORT` | `4000` | HTTP port |
| `HOST` | `127.0.0.1` | Bind address |
| `DB_PATH` | `./data/crewsignal.db` | SQLite file (`:memory:` in tests) |
| `CORS_ORIGIN` | `http://localhost:3000` | Comma-separated allowed browser origins |
| `CREW_KEY` | `crew-demo-key` | Bearer key with the `crew` role |
| `GROUND_KEY` | `ground-demo-key` | Bearer key with the `ground` role |
| `DEVICE_KEY` | `device-demo-key` | Bearer key with the `device` role |
| `DELAY_SCALE` | `1` | Multiplies the scenario one-way delay |

Keys must be at least 8 characters; change them outside the demo.

## Run

```bash
cd backend
npm install
npm run dev        # tsx watch
npm test           # 20 tests, fake clock, no sleeps
npm run build      # tsc -> dist/
npm start          # node dist/server.js
npm run fake-device
```

The database is created on first start. WAL is enabled, and every transition is
computed from stored timestamps, so restarting mid-flight neither loses nor
duplicates a delivery.

## Demo recipe: a one-minute Mars delay

```bash
DELAY_SCALE=0.05 npm run dev
```

Mars transit is 1200 s one-way, so `0.05` gives 60 s. `GET /health` and
`GET /v1/link` return both `scenarioDelaySeconds` (1200) and
`effectiveDelaySeconds` (60), and the ribbon labels the compression instead of
pretending the link is real.

## Full queued → sent → delivered → acknowledged flow

```bash
API=http://127.0.0.1:4000
CREW="Authorization: Bearer crew-demo-key"
GROUND="Authorization: Bearer ground-demo-key"
JSON="Content-Type: application/json"

# 1. Health and link
curl -s $API/health
curl -s -H "$CREW" $API/v1/link

# 2. One-way delay of 60 s
curl -s -X PUT -H "$CREW" -H "$JSON" $API/v1/link \
  -d '{"state":"delayed","environment":"mars_transit"}'

# 3. Post a handoff (id is generated by the client)
curl -s -X POST -H "$CREW" -H "$JSON" $API/v1/packets -d '{
  "id":"handoff-001",
  "crewId":"alex-morgan",
  "kind":"handoff",
  "createdAt":"2026-01-01T10:00:00.000Z",
  "title":"Handoff",
  "private":false,
  "includePrivate":false,
  "payload":{"observations":[{"metric":"heart_rate","value":84}]},
  "history":[]
}'
# -> state "sent", visibleAt = sentAt + 60 s

# 4. Before visibleAt
curl -s -H "$CREW" "$API/v1/packets/handoff-001?crewId=alex-morgan"
# -> state "sent"

# 5. After visibleAt (the scheduler tick promotes it)
sleep 61
curl -s -H "$CREW" "$API/v1/packets/handoff-001?crewId=alex-morgan"
# -> state "delivered"

# 6. Ground inbox, then acknowledge
curl -s -H "$GROUND" $API/v1/surgeon/inbox
curl -s -X POST -H "$GROUND" $API/v1/surgeon/packets/handoff-001/ack
# -> ackAt set, ackVisibleAt = now + 60 s, state still "delivered" for the crew

# 7. After the return delay
sleep 61
curl -s -H "$CREW" "$API/v1/packets/handoff-001?crewId=alex-morgan"
# -> state "acknowledged"
```

Blackout stores nothing:

```bash
curl -s -X PUT -H "$CREW" -H "$JSON" $API/v1/link \
  -d '{"state":"blackout","environment":"mars_transit"}'
curl -s -X POST -H "$CREW" -H "$JSON" $API/v1/packets -d '{...}'
# -> 503 {"error":{"code":"LINK_BLACKOUT", ...}} and no row is written
```

## Sync

```bash
curl -s -X POST -H "$CREW" -H "$JSON" $API/v1/sync/observations -d '[{
  "id":"obs-1","crewId":"alex-morgan","metric":"heart_rate","value":82,
  "unit":"bpm","observedAt":"2026-01-01T09:58:00.000Z",
  "enteredAt":"2026-01-01T10:00:00.000Z","lane":"manual","method":"cuff",
  "context":"rest","quality":"ok","qualityReason":null,
  "environment":"mars_transit","procedureVersion":"demo-procedures-1"
}]'

curl -s -H "$CREW" "$API/v1/sync/observations?crewId=alex-morgan&since=0"
```

Observations are immutable except the quality fields. The server reruns the
demo gate for manual and live rows; replay and synthetic rows never become
stale. When client and server disagree, the stricter flag is stored and the
reason records both.

## Device ingest and stream

```bash
DEVICE_ID=pulse-01 CREW_ID=alex-morgan npm run fake-device
```

One sample per second, with eight seconds of contact loss every minute. `none`
becomes `no_contact`; `poor` with motion above 0.5 g becomes a motion artifact.
The sample is stored in the live lane and pushed to stream clients.

```bash
curl -N "$API/v1/stream?token=ground-demo-key"
# event: link.changed / packet.delivered / packet.acknowledged / sample
```

The stream route accepts `?token=` only because `EventSource` cannot send
headers. Heartbeats are comments every 15 s and listeners are removed on
disconnect.

## Audit

```bash
curl -s -H "$GROUND" $API/v1/audit/verify
# {"ok":true,"checked":N,...}

sqlite3 data/crewsignal.db "UPDATE audit_log SET action='edited' WHERE id=1;"
curl -s -H "$GROUND" $API/v1/audit/verify
# {"ok":false,"firstBrokenId":1,"expected":"...","actual":"..."}
```

Each row hashes the previous hash plus the canonical JSON of the row, so an edit
breaks every later hash. This is tamper evidence, not tamper prevention.

## Linking the frontend

In `frontend/.env.local`:

```
NEXT_PUBLIC_API_URL=http://localhost:4000
NEXT_PUBLIC_CREW_KEY=crew-demo-key
NEXT_PUBLIC_GROUND_KEY=ground-demo-key
```

Then run the frontend on `http://localhost:3000` and the backend on
`http://localhost:4000`. Both must stay on plain `http://localhost`: a browser
will not open SSE or fetch from an `https` page to a plain-HTTP LAN address, and
a self-signed certificate needs its own trust step. Keeping both on localhost
avoids mixed-content blocking without adding TLS to a demo.

With `NEXT_PUBLIC_API_URL` unset, the frontend is the original offline demo and
all existing tests pass unchanged.

## What this is not

This is demo software. The keys are shared secrets checked by string equality,
there is no TLS, no per-user identity, and no claim of medical-data security or
HIPAA/GDPR compliance. Private mood, stress, rested and connected fields are
stripped server-side as defense in depth, but the transport is plain HTTP in the
demo.
